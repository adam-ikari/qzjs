## 决策三原则 + 极简哲学（用户拍板，项目级约束）

任何设计/方案/取舍讨论，必须先满足这几条约束，缺一不推进：

1. **苏格拉底式提问（先问再答）**
   - 方案提出前，先以提问收敛问题本质：场景是什么、约束是什么、目标量级是多少、可接受边界在哪。
   - 用"已知事实 vs 假设"区分证据与猜测；对未实证的假设先设计探针/测量，再谈方案。
   - 例：polyfill 启动加速——先问"加速哪个场景（首启/spawn）""2ms 里哪些可省"再落方案。

2. **第一性原理（从事实推导，不搬套路）**
   - 拆到不可再分的物理/引擎事实再重建：QuickJS 字节码 realm 绑定、ReadObject 为一次性反序列化、lazy 只省 setup 执行。
   - 禁止"业界都是这么做的""别人用了 X"式论证；每个主张须可实测或可证伪。
   - 收益必须量化到具体数值（ms/字节），不接收"更规范/更优雅"的抽象收益。

3. **奥卡姆剃刀（决策层：取最小可行方案）**
   - 两个方案同收益取实现更小的；无法实证收益的方案直接砍。
   - 复杂度=负债：预热池（跨 realm 不可共享、驻留内存、槽位迁移）即因过复杂被否决，改为保留已实现的属性级懒加载。
   - 不建无消费者验证的抽象层，不预埋"将来可能用到"的机制。

4. **极简哲学（产物层：项目本身要极简）**
   - 第 3 条管「怎么选方案」，本条管「产出物本身」。
   - **意义（极简换来什么，四个维度）**：
     1. **减少维护的负担**——代码量即阅读/评审/升级成本。
     2. **减少潜在的问题**——分支、状态、路径都是缺陷机会。
     3. **减少运行时开销**——少一层的间接、少一份缓存、少一次拷贝。
     4. **减少受到攻击的面**——每一处状态/能力都是可被触达的入口。
   - 前三条是「成本」，第四条是「安全」：多暴露一个能力、多解析一份输入、多存一份
     状态，都在扩大可被攻击的表面积。严格模式（限 fs 根、锁 spawn、白名单 env）
     正是这条原则的产物；每新增一个开关/后门/协议字段都要自问是否在扩这张表。
   - **动作**：删优于加、改优于建——能用现有代码表达就别加一整个文件；能删就别留
     兼容别名/废弃路径/无人读的文档段。拒绝"为了对称/可扩展/看起来完整"的膨胀：
     读者用不到、测试跑不到、评审问不出具体场景的代码段就是负债。
   - **抽象只在已出现第二个真实消费者时才提取**（rule of two）：第一个消费者出现时，
     允许重复，不允许提前抽象。
   - **判据**：任何新增产物都要能说清它在上述四个维度上省了什么或省不了什么；
     四项皆无 → 不写。说不清比值就不写。

## 验证前提：三原则在「测试验证」上的追加约束（2026-09-30 补）

上述原则管「想得对不对」，本节管**「验得对不对」**——由 P1 e2e 收敛的真实回归换来。

**核心失效模式：基线对照在「基线本来就红」时零证明力。**
P1 改 e2e 脚本时，5 个多进程脚本因 `spawnWorker failed (err -9)`（worker spawn 本身
坏 + 残留进程）全部失败；我用「基线也失败 ⇒ 非我引入」结束调查。但基线全红时，二值
对照**无法区分**「改动中性」与「改动引入了被既有失败遮住的新缺陷」。nested e2e 的
`GROUPS` 回归（见下）就是这样活过 P1 全程的，直到环境修好才暴露。

**硬性要求**：
1. **改测试脚本前先让基线可绿**。基线红着改测试 = 在无法判定真伪的场地施工。顺序：
   清残留进程/临时文件 → 确认至少一个同类 e2e 能 PASS → 再动脚本 → 逐个跑。
2. **判定回归要看「同一条断言」，不看「整体通过/失败」**。二值信号是回归的天然藏身
   处。基线红时改为逐条 diff 失败点。
3. **两处以上同失败不等于一个原因**。表面三异（err -9 / unbound var / ENOENT）实为
   三个不同根因（交叉误杀 / 自身变量名撞 shell 特殊变量 / 宿主 FS 异常）。奥卡姆剃刀
   要求「最简解释覆盖全部症状」，但更前的动作是**先把症状拆开**再套最简解释。

**顺带记两条具体教训**：
- **基线对照的正确用法是「改动前后跑同一环境」**，不是「跑一次能过就行」；且要求能
  复现（连跑多次同结果），不能拿单次结果当证据。
- **shell 变量名/数组名先查是否特殊**。`GROUPS` 是 bash 内建（当前用户组列表），
  `GROUPS+=(...)` 在 `set -u` 下会让函数调用中止其调用者——这个坑当时靠隔离出 10 行
  复现脚本才抓到，纯读 1400 行脚本不可能发现。**能隔离就不要通读**。

## 适用

- 特性/架构取舍、性能优化、依赖引入、接口设计的前置讨论。
- **测试/e2e 脚本改动、回归判定**（新增「验证前提」一节）。
- **任何新增代码/文档/结构/能力开关**（第 4 条：产物层极简 + 攻击面）。
- 产出物：先提问清单 → 实测数据 → 最小方案；拒绝未经测量的方案陈述。
