# 科学计算性能基准（2026-10-21 实测）

**一句话**：AOT 在 `num` 快路径（纯数值、无数组/对象）上比解释器快 **10-42×**、与 V8 JIT 同档（0.4-2.8×）；一旦落入 `tagged` 路径（局部数组、箭头函数、属性访问），比解释器**慢 5-30×**。

复现：
```
WAMRC=deps/wamr/wamr-compiler/build/wamrc node src/qzvm/aot/bench_scin.js --build
```

## 实测结果

| Lorenz RK4 2e4 步 | num | 0.69 | 11.75 | 0.50 | **17.0×** | 0.72× |

## 关键结论

**1. 模式判定是性能的分水岭。** `emitter.js:funcMode()` 要求函数体不含数组字面量、
箭头函数、属性访问、`new`、模板串等，才编成 `num`（f64 直算）。命中任一 → `tagged`
（句柄 + 内存读写 + 每次操作调宿主导入）。

同样的 N 体算法：

| 写法 | 模式 | AOT ms | 相对 V8 |
|---|---|---:|---:|
| `px[i]`/`py[i]` 局部数组 | tagged | 426.26 | **0.002×** |
| 标量累加（无数组） | num | 1.77 | 1.94× |

**差 241 倍。** 这是科学计算可用性的核心约束：**数值密集算法要用标量/定长展开写，
不要用数组。**

**2. num 路径已超 V8 的 4 项**：Mandelbrot 0.88×、Lorenz 0.72×、张量积 0.40×、
素数筛 1.13×。原因是 AOT 无 JIT 预热、无去优化、无 GC 压力。

**3. tagged 路径对科学计算不可用。** 蒙特卡洛 5e5 点用数组存点 → 4.4 秒，而标量版
8.23 ms。差值全部来自 `arr.push` / `arr[i]` 的宿主导入往返。

## 对写代码的指导

要 AOT 提速，函数必须保持 `num` 模式：

- ✅ 标量局部变量、`for` 循环、`+ - * / %`、`Math.sqrt/abs/floor`
- ✅ 递归（`fib` 实测快 26×）
- ❌ 局部数组 `const a: number[] = []`（含 `push`/下标读）
- ❌ 箭头函数 / 闭包
- ❌ 属性访问 `obj.x`、类实例字段
- ❌ `Math.random`（改线性同余伪随机，实测可用）

定长状态用**多个标量变量**（`x0..x31`）而非数组，或把数组提到模块级
（模块级数组字面量仍判 `ArrayLiteral` → tagged，需用其它手段）。

## 影响面

`READINESS.md` 的「数值/计算密集场景可用」结论成立，但**前提更严**：
不只是"无对象 I/O"，而是**完全不用数组**。真实科学计算库（矩阵、向量）几乎必用
数组，因此现状下 AOT 难以直接提速这类代码。

**下一步优先级**：把 `num` 路径扩展到「数值型数组」（定长 `Float64Array` 或
编译期可推断长度的 `number[]`），消除数组依赖的强制 tagged 降级。这是把 AOT 从
"数值玩具"变成"科学计算可用"的关键一步。
